{! pages/reportes/index - Reportes navigation hub (link list to every report). Rendered by GET /app/reportes (MiscPagesResource). Mirror of the legacy Registros/index.xhtml four-card dashboard (Facturación / Recibos / Inventarios / Usuarios with colored header bars), repointed at the real /app routes of the new surface. Button parity notes: - Every legacy button appears, mapped to its new route (Órdenes de Compra -> /api/app/ordenes/table, full page when opened without HTMX; Resumen de Impuestos -> /app/tributacion/declaracion, etc.). - Legacy Departamentos/Familias catalog reports and the Scorecard de Proveedores had no dedicated new route; /app/categorias is the closest equivalent (it renders the departamentos, familias and supplier-metrics sections), so those buttons point there. - New-only reports added into their matching group (Estacionalidad, Recibos Pendientes/Vencidos, Mermas, Histórico de Precios). - Visibility mirrors the legacy page: buttons are shown to every role and the destination pages enforce their own gates; only "Registros Internos" stays admin-gated (as in legacy rendered="#{SessionController.admin}"). WHAT CHANGED IN THE UI PASS --------------------------- - The title is the kit's _kit/page-header: exactly one

, with the scope in the muted subtitle. The hub's single control - the client-side search - lives in the header's {#actions} slot, so it reads as the page's toolbar instead of a field floating above four cards. - The hub is ONE column of four groups. It used to be four is-one-quarter columns whose cards started at four different heights (a 282px spread), so no two cards began on the same line. - Each group is a .surface. The header is written out (the component has no icon parameter) with the component's own classes, so the group keeps a leading _kit/icon, a real

, a one-line description and the number of reports in the group. The heading order of the page is h1 -> h2. The group titles used to be

, which is not a heading at all, and at 20px/800 they read LOUDER than the page's own

. - The links are QUIET rows, not thirty-two filled buttons of the same weight (ui-kit 10.1: "A hub of report links is a LIST, not twenty buttons: the links are quiet and the card titles carry the structure"). Each row is a .menu-list link: name in the normal ink, an optional one-line description lifted from the link's own title attribute in the muted ink, and a muted arrow that marks where the row goes. The rules between rows are drawn with the design token, so they follow the colour scheme. - Every report, its href and its title attribute are unchanged. WHY THE RULES ARE border-top AND NOT border-bottom --------------------------------------------------- The first row of a group carries no rule; every following row carries one above it. With border-bottom, the last row of each group needed a manual exception and the admin-only "Registros Internos" link left the exception on the wrong row for non-admin users. border-top keeps a trailing rule out of the card body no matter which row renders last. !} {#include layout} {#title}Reportes | Mercurius{/title} {#body} {! Client-side filter: the hub is a list of links and the backend exposes no search key, so the filtering happens in the browser over the rendered labels. Alpine owns one string; each link and each group is shown only while its own text matches. No request, no backend key, and the hub still works as plain links with JS off. The search matches the visible description too, which is why it is labelled "Nombre o destino". !}
