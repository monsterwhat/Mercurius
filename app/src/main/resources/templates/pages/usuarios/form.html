{! pages/usuarios/form - modal-body form for crear|editar usuario (W4B lane). Returned by GET /api/app/users/formularios[/nuevo|/{id}] and re-rendered by the form-urlencoded POST/PUT twins on validation failure (ui-kit.md Pattern A: fragment redisplay + out-of-band toast). Field names are verbatim ports of CreateUsersDialog.xhtml / EditUsersDialog.xhtml ("Nombre de usuario:", "Contraseña:", "Permisos:"). The visible labels drop the trailing colon and the permisos checkboxes carry a one-line description of what each module grants. The permisos checkboxes reproduce UsersController's Arrays.toString(selectedPuestos) groupName storage format ("[a, b]"), which Services.auth.UserRoleMapper parses back into role tokens. EDIT MODE IS TWO FORMS, ON PURPOSE ---------------------------------- PUT /{id}/permisos updates ONLY groupName and PUT /{id} updates ONLY username/email. The old single form posted username+email to the permisos endpoint, so edits to those two fields were silently discarded. The dialog now renders one form per endpoint, each with its own submit, so nothing a user types is thrown away. Model: modo String - "crear" | "editar" usuario Object - Models.Usuarios when editar, null when crear (the create form is only served to admins — GET /formularios/nuevo is @RolesAllowed("admin") — so the "Administrativo" checkbox needs no per-request gate, unlike the legacy rendered="#{SessionController.admin}") errorUsuario String - blank-username error (legacy requiredMessage) errorPassword String - blank-password error (crear only) errorPermisos String - no-permisos / invalid-token error (crear and editar) errorGeneral String - guard failures surfaced by the API (duplicate username) shown under the form + as toast toastSeverity String - OOB toast severity (nullable) toastMessage String - OOB toast text (nullable) !}
