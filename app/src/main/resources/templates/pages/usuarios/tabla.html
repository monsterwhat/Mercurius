{! pages/usuarios/tabla - ONE data-table include for the Usuarios module (W4B lane). Rendered standalone by GET /api/app/users/table when the HX-Request header is present (fragment swap) AND included by index.html — single source of truth for the markup (T18 pattern). Model (identical contract to pages/categorias/tabla-*.html): modelo Map - id, baseUrl, columnas(label/key), filas(Models.Usuarios), sortKey, sortDir, page, size, total, totalPages, paginas, filtros(reserved keys excluded), q q String - current search text (round-tripped into the input) toastSeverity / toastMessage - optional OOB toast after row actions Columns mirror UsersTableDetallado.xhtml: Identificador de perfil, Nombre de usuario, Nombre del grupo, Activo + Acciones. Filter parity: case-insensitive contains over username/email/groupName (UsersController.globalFilterFunction port). Row actions: edit opens the shared modal via data-kit-open + hx-get; archive is the REST soft-delete (DELETE = status=false parity with UsersController.deleteUser()). WHAT CHANGED IN THE UI PASS --------------------------- - The wrapper is a _kit/surface (no title: the panel has no heading). It KEEPS its id, because that element IS the hx-target of the search input and of the row actions - the swap replaces the whole surface. - The row actions are icon-only BORDERED buttons (kit icons, own aria-label). They used to carry is-success / is-warning, which put a second and a third accent hue on a screen whose only accent is teal. - The profile identifier is a KEY, so it is set in .kit-code (the app's one monospace class) and stays left-aligned; it is not a quantity, so it does not take `num`. !} {#include _kit/surface id=modelo.id} {#content}
