{! pages/facturas/checkout-dialog - the ONE payment surface of the POS. Facturar opens it (data-kit-open="modal-cobro" + hx-get on the cart panel button); GET /api/app/pos/checkout-dialog renders this body. It is fetched on every open, so the total and the exchange rate are always the ones the current cart shows - never a value frozen when the page loaded. The cashier answers exactly one question: how much did the customer hand over, in colones and/or in dollars. There is no payment-method selector: cash is split across the two currencies, nothing else. Live math (client-side, this fragment only): pagado = colones + dolares x tipo de cambio vuelto = pagado - total Facturar stays disabled while pagado < total, so the server-side "FALTANTE_DE_PAGO" guard is a backstop, not the normal path. The server converts the dollars itself (same venta rate) and runs the SAME facturar pipeline - this dialog adds no business logic. Model ("cobro" bound key, Map): total BigDecimal - cart total to pay (server-computed) totalRaw String - the same value as a plain decimal for JS disponible bool - a venta exchange rate exists tipoCambio BigDecimal - venta rate, null when unavailable tipoCambioRaw String - plain decimal, "0" when unavailable !}
