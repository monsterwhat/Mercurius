ONE DATASET, ONE TABLE ON SCREEN -------------------------------- The four tables are four VIEWS of the same comprobantes-emitidos dataset (todas / pagadas / procesadas / vencidos). Rendering all four made the screen two screens tall and left the clerk unable to tell which bucket they were reading, so they read all of them. The board now shows ONE bucket at a time: _kit/view-tabs carries the counts and the Alpine `bucket` variable picks the visible panel. The Alpine scope lives on this
, ABOVE the #recibos-tablero swap target. A row action re-renders the whole board (outerHTML on #recibos-tablero); a scope declared inside the board would be destroyed and rebuilt with every action, throwing the operator back to the first bucket. Here the scope survives, so the bucket they picked survives too.
