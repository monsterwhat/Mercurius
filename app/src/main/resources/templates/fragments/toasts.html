{! fragments/toasts - Bulma notification stack rendered from the "toasts" data model (T11). Data contract: "toasts" is a list of items exposing: severity : String - one of error | warn | info | success (mirrors the legacy FacesMessage severities used across SessionController.errorMessage/infoMessage/warnMessage plus the ubiquitous "Exito" success case; anything else falls back to info) message : String - auto-escaped by Qute for .html templates The layout renders this fragment inside #toast-container only when the page supplies a "toasts" key ({#if toasts??} safe expression), so pages without notifications pay nothing. Each item is the ONE toast component (_kit/toast-item). This file used to be a second, hand-copied toast implementation: it gave every item role="alert" (a burst of successes interrupted the screen reader), and its own DOMContentLoaded script double-bound the dismiss button that _kit/toast-item had already bound. Rendering the component here removes both defects and keeps one definition of severity, role and lifetime. !} {#for toast in toasts} {#include _kit/toast-item severity=toast.severity message=toast.message /} {/for}
