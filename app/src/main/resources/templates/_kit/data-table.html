{! _kit/data-table - shared server-paged/sorted table (T16). Replaces the legacy p:dataTable (+ p:column). ALL state lives in the URL; this fragment never holds state and embeds NO business logic. SERVER-SIDE PAGING/SORTING CONTRACT ----------------------------------- The table links back to the SAME endpoint that rendered the page: GET {baseUrl}?page=N&size=S&sort=&dir=asc|desc[&] The resource must: - read page/size/sort/dir from query params (sane defaults: page=1, size=20, sort=null, dir="asc"), - when the request carries the "HX-Request" header, render ONLY this table include (fragment swap into the page's table container); otherwise render the full page template, - keep totalPages = ceil(total/size) server-side (Qute has no division), - pass filters/sort/dir back down through the "params" map so pager and sort links preserve them, - treat "page", "size", "sort", "dir" as RESERVED query keys: they are emitted by this fragment and must NOT appear in "params". DATA CONTRACT (params of this include): id String - REQUIRED. DOM id of the wrapper div. baseUrl String - REQUIRED context-path-relative endpoint, e.g. "/app/articulos". Root-path prefix is added HERE. headers List - REQUIRED. Column definitions as maps, each exposing "label" (always), "key" (nullable -> column is NOT sortable when key is absent/null) and "num" (optional Boolean -> the column holds figures, so it is right-aligned with tabular numerals; the header gets the same treatment so the two line up). Build them server-side e.g. Map.of("label","Nombre","key","nombre"). rows List - row data for rowFragment mode (see below). rowFragment String - OPTIONAL root-relative template path, e.g. "_kit/rows/articulo". When set, tbody renders one include per item: {#include _id=rowFragment item=row rowIndex=row_index /}. When ABSENT, tbody renders the caller's {#rows}...{/rows} block instead (caller owns iteration AND its empty-state). sortKey String - OPTIONAL currently sorted column key. sortDir String - OPTIONAL current direction, "asc"|"desc". label String - OPTIONAL accessible name for the scroll region; default "Tabla de resultados". Pass a specific name when a page renders more than one table. emptyLabel String - OPTIONAL empty-state text for rowFragment mode; default "Sin registros". page Integer - OPTIONAL current 1-based page (footer/pager). size Integer - OPTIONAL page size, echoed into links. total Long - OPTIONAL total row count, shown in the footer. totalPages Integer - OPTIONAL; when present (>1) the pager renders. pages List - OPTIONAL window of page numbers for the pager (server-computed, see _kit/pagination). params Map - OPTIONAL preserved query params (URL-safe values; reserved keys excluded). SORT LINKS: each sortable header emits ?sort=&dir= plus preserved params, targeting the same endpoint. Clicking a sorted column flips asc->desc; clicking another column starts at asc. aria-sort marks the active column for screen readers. The ▲/▼ glyph is aria-hidden: the sort state is announced by aria-sort, not by a shape. SLOTS {#caption} - OPTIONAL. Rendered inside before the header row, for a visible
describing the dataset. A is the table's accessible name; supply it when the surrounding surface title does not already name the data. {#rows} - the body rows (caller owns iteration AND its empty state). When rowFragment mode is used this slot renders its own empty row. ZEBRA STRIPING IS GONE The table used to carry Bulma's `is-striped`. Banded rows make a dense table louder than its data and hide where one record ends and the next begins; Bulma's own row rules already do that job. `is-hoverable` stays: a row that responds to the pointer is what lets an operator find their place in a 40-row list. !} {@java.lang.String id} {@java.lang.String baseUrl} {@java.util.List> headers} {! Only id/baseUrl/headers are declared: the remaining parameters are OPTIONAL per the data contract above, and {@...} declarations make Qute fail rendering when a caller omits them. Optional usages are ??-guarded. !} {! The id lives on .table-block, NOT on the scroll frame. The pager must sit outside .table-container: a phone-sized viewport turns the container into a horizontal scroller as wide as the table, so a pager rendered inside it is parked past the last column and the operator never sees it. HTMX swaps still target #{id}, which now replaces table + pager as one unit. !}
