{! _kit/pagination - Bulma pager for server-side paging (T16). Renders a centered Bulma pagination bar (first / prev / page numbers / next / last). Every link targets the SAME endpoint that rendered the current view, differing only in query params, so both full-page navigation and HTMX boosted navigation work. To boost it, wrap the include in an element with hx-boost="true" or target the table container from the page. DATA CONTRACT (all supplied by the calling resource/template): page Integer - current page, 1-based. REQUIRED. totalPages Integer - total number of pages (server computes ceil(total/size); Qute has no division). REQUIRED. pages List - OPTIONAL. The window of page numbers to render as numbered links (e.g. [1,2,3,4,5]); the SERVER decides the window so this template stays arithmetic-free. When absent only prev/next render. baseUrl String - context-path-relative endpoint, e.g. "/app/articulos". The deployment root is read from configuration ({config:['quarkus.http.root-path']}) and prepended HERE - callers must NOT pre-prefix it. params Map - OPTIONAL extra query params preserved on every emitted href (filters, sort, dir...). Values must already be URL-safe: no encoding is performed here. RESERVED KEYS that must NOT be in the map: "page" and "size" (emitted by this template itself). LINK SHAPE produced: {root-path}{baseUrl}?page=N[&size=S][&k=v ...] ("page" first, then every preserved param prefixed with "&", so no separator logic is needed inside the template). !} {@java.lang.Integer page} {@java.lang.Integer totalPages} {@java.lang.String baseUrl} {! pages stays undeclared: it is OPTIONAL and ??-guarded below. Declaring it with {@...} made Qute fail rendering when a caller omitted the numbered window, which is the exact case the `{#if pages??}` guard exists for. !} {! params stays undeclared: it is optional and ??-guarded below. !}
