{! _kit/toast-item - ONE notification, severity-mapped to Bulma colors (T16). Replaces the legacy p:growl. Two usage modes: 1) Server-side render: a resource includes this fragment (directly or via fragments/toasts-style loops) when rendering a page that must show notifications immediately. 2) HTMX swap: the response fragment wraps this include in an out-of-band swap so the toast lands in the layout's #toast-container without touching the requested target:
{#include _kit/toast-item severity="success" message=result.message /}
(htmx inserts the CONTENT of an hx-swap-oob element using the named swap style; "beforeend" appends into the container.) DATA CONTRACT: severity String - accepted values, case-insensitive: error / ERROR -> is-danger warn / warning / WARN... -> is-warning success / SUCCESS -> is-success anything else -> is-info (default) This covers both the T11 lowercase vocabulary (fragments/toasts.html) and raw FacesMessage-style uppercase severities coming from ported services. message String - auto-escaped by Qute (.html template). BEHAVIOUR lives in web/index.js (kitToasts), not in an inline script: a MutationObserver on #toast-container binds every item, whether it was server-rendered or appended by an hx-swap-oob response, and gives it the dismiss button, the pause-on-focus countdown and the 5s auto-dismiss. Keeping the lifecycle out of this template means a swapped toast cannot install a second copy of the same script, and fragments/toasts.html can render this component without a competing implementation. A failure interrupts (role="alert"); everything else is announced politely (role="status"). An error stays until it is dismissed: five seconds is not enough to read a failure and decide what to do about it. !} {@java.lang.String severity} {@java.lang.String message}
