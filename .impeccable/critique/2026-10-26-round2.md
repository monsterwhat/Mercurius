## 1. P0 — blocking

### P0-1 · The filter bar's primary button is outside its form (8 pages)

**Where (shared, one fix):** `app/src/main/resources/templates/_kit/filter-bar.html:65-72`

```56:72:app/src/main/resources/templates/_kit/filter-bar.html
<section class="filter-bar"{#if id??} id="{id}"{/if}>
    <form class="filter-grid" method="{method ?: 'get'}"{#if action??} action="…"{/if}>
        {#insert}{/insert}
    </form>
    <div class="filter-actions">
        {#insert actions}{/insert}
    </div>
</section>
```

`{#insert actions}` renders **after** `</form>`, and no page passes a `form="…"` attribute, so every `type="submit"` in that slot is associated with no form. It is not a “wrong submit target” — it is a submit button with no form owner, which the browser ignores.

**Affected pages** (all pass `{#actions}` with a submit; all but `margenes` have **zero** `hx-get`/`hx-trigger` inside their filter block, so the button is the *only* way to apply the filter):

| Page | Dead button | Other trigger? |
|---|---|---|
| `pages/reportes/tendencias.html:41` | Cargar Datos | none (plain `<input type="date">` at :31,:37) |
| `pages/reportes/estacionalidad.html:36` | Actualizar | none (:29,:33) |
| `pages/reportes/resumen.html:72` | Filtrar | none |
| `pages/reportes/alertas.html:76` | Filtrar | none (selects at :53,:65) |
| `pages/reportes/merma.html:45` | Actualizar | none |
| `pages/reportes/pronosticos.html:72` | Generar pronóstico | none |
| `pages/reportes/rendimiento.html:40` | Cargar Datos | none |
| `pages/reportes/margenes.html:68` | Generar Análisis | yes — every control carries `hx-get` (:24-27, :32-35, :41-44, :56-59); the button is still dead |

**Why it matters:** on seven screens the operator fills the date range, presses the screen's only filled primary, and nothing happens. Implicit Enter submission is not a rescue: with 2+ fields and no associated submit button, browsers do not reliably submit. This is a functional blocker on the entire report surface, and it reads as “the app is broken”, not “I missed a filter”.

**Exact change (shared component, keeps every caller working):**

```html
<section class="filter-bar"{#if id??} id="{id}"{/if}>
    <form class="filter-bar-form" method="{method ?: 'get'}"{#if action??} action="…"{/if}>
        <div class="filter-grid">{#insert}{/insert}</div>
        <div class="filter-actions">{#insert actions}{/insert}</div>
    </form>
</section>
```

and in `web/mercurius.scss` §7 move the flex container from `.filter-bar` to `.filter-bar-form` (`.filter-bar { display:block; padding:…; }` / `.filter-bar-form { align-items:flex-end; display:flex; flex-wrap:wrap; gap:var(--mercurius-space-3); justify-content:space-between; }`), keeping the existing `1091-1193` breakpoints pointed at `.filter-bar-form`.

Note the `id` currently lands on the `<section>` while `filter-bar.html:16-18` documents it as “put it on the `<form>` so `hx-include="closest form"` works”. `hx-include="#filtros-x"` (`pages/stockalert-config/index.html:77,89,102`) still resolves through the section, so the fix must keep the id where it is — or move it to the form and update those three call sites.

## 2. P1 — high

### P1-1 · Search-as-you-type loses focus and caret because the input has no `id`
**Page-local pattern, 17 files.** The search input lives *inside* the element it swaps (`hx-swap="outerHTML"` on the wrapper that contains the input). htmx restores focus after a swap only by re-finding an element with the **same `id`**; these inputs have none.

Clearest instance — `pages/articulos/tabla-articulos.html:50-62`: wrapper `id="{modelo.id}"` is the `hx-target`, and `<input class="input" type="text" name="q" …>` at :54 has no `id`.

Same shape in: `articulos/buscador-cabys.html:24`, `articulos/selector-articulos.html:24`, `articulos/selector-articulos-ajuste.html:24`, `articulos/tabla-promociones.html:39`, `cabys/tabla.html:38`, `categorias/tabla-departamentos.html:21`, `categorias/tabla-familias.html:37`, `clientes/tabla.html:39`, `compras/ordenes-tabla.html:41`, `correos/tabla-reportes.html:42`, `inventario/tabla-{activos:34,inactivos:23,pendientes:24,procesados:24}.html`, `recibos/tabla.html:33`, `usuarios/tabla.html:40`, `facturas/articulos-picker.html:26`.

**Why:** type “cami”, pause 300 ms, the box swaps and the caret is gone; the next keystrokes go to `body`. On the POS pickers the same bug makes a 250 ms pause feel like a freeze.
**Fix:** give each input a stable, unique id (`id="{modelo.id}-q"`, `id="cabys-q"`, …). The five correct implementations already do this: `facturas/client-picker.html:24` (`client-picker-q`), `facturas-recibidas/tabla.html:49`, `stockalert-config/index.html:76`, `reportes/clientes.html:27` and siblings. Copy that.

### P1-2 · Failed HTMX requests are silent app-wide
`web/index.js:297-310` installs `kitBridge/kitUploadProgress/kitPolling/kitPopup` and no error hooks. Only 3 of 147 templates listen to any HTMX failure (`pages/cabys/index.html:65`, `pages/settings/index.html:30,849`).
**Why:** a 500/403/timeout during a filter, a modal body load, a row deactivate or a settings save leaves the previous DOM in place with no message. The operator re-clicks; the request is duplicated. The toast infrastructure to fix this already exists (`_kit/toast-container` + `_kit/toast-item`).
**Fix (shared, `web/index.js`, inside `boot()`):**
```js
['htmx:responseError','htmx:sendError','htmx:timeout'].forEach(function (n) {
    document.body.addEventListener(n, function (evt) {
        var status = evt.detail && evt.detail.xhr ? evt.detail.xhr.status : 0;
        window.mercuriusToast('error', status === 403
            ? 'No tiene permiso para realizar esta acción.'
            : 'No se pudo completar la operación. Intente de nuevo.');
    });
});
```
plus a tiny `mercuriusToast(severity, message)` in `web/index.js` that appends a `_kit/toast-item`-shaped node into `#toast-container`. That is the same DOM the server already emits, so no new component.

### P1-3 · Async regions are silent to screen readers (variant of a pattern that already exists)
Only ~17 live-region declarations exist in the entire tree (`aria-live`, `role="status"` or `role="alert"`), and they are the toasts, the POS, the login error and `loyalty/index.html:58`. The regions that actually swap content have none:

| Region | Where |
|---|---|
| report/board table containers (`#reporte-tabla`, `#{modelo.id}`) | all `pages/reportes/_tablas/*`, `pages/*/tabla*.html` |
| `#upload-resultado`, `#upload-resultado-recibos`, `#inventario-upload-resultado` | `facturas-recibidas/index.html:56`, `recibos/index.html:74`, `inventario/index.html:73` |
| `#prevalidacion-panel` | `facturas-recibidas/detalle-drawer.html:67-69` |
| `#consultas-countdown` | `tributacion/consultas.html:43-48` |
| `#historica-estado` (“Cargando datos…”) | `reportes/ventas-fecha-historica.html:93` |

**Why:** filtering a 200-row report or loading a modal drawer produces a visual change and no announcement; a blind operator cannot tell a filter applied, a load finished, or a save failed.
**Fix:** copy the implementation that already works — `pages/loyalty/index.html:58` (`<p id="…-anuncio" class="is-sr-only" role="status" aria-live="polite">`) plus `104-128` (`htmx:afterSwap` → announce “Historial cargado” / focus the first `[aria-invalid="true"]`). For tables, one shared line in the swap target: `<p class="is-sr-only" role="status" aria-live="polite">{modelo.total} resultados</p>`. `#historica-estado` should become `role="status"` and must not stay on “Cargando datos…” forever (see P2-9).

### P1-4 · The inventory badges poll destroys the operator's focus every 30 s
`pages/inventario/index.html:46-50` wraps **the tab switcher itself** in `hx-get … hx-trigger="every 30s" hx-swap="innerHTML"`, and the fragment it swaps (`pages/inventario/badges.html:12-35`) is four `<button>`s.
**Why:** a keyboard user tabbing onto “Pendientes” at second 29 loses focus to `body` at second 30; the panel they were reading re-renders underneath them. It also has no `aria-live`, so nothing is announced when counts move.
**Fix (page-local):** poll the *counts*, not the controls. Either (a) keep the buttons in `index.html` and give each `.view-tab-count` an id that a small `hx-get` swaps (`hx-trigger="every 30s"` on a hidden `<span>` per count), or (b) add `hx-preserve="true"` to the nav. Additionally adopt the documented polling helper: add `data-poll data-poll-age="#inventario-edad"` (the helper exists in `web/index.js:165-234` and is currently unused — see P2-4).

### P1-5 · Alpine view switchers expose no selected state to assistive tech
Data-mode `_kit/view-tabs` correctly emits `aria-current="page"` (`_kit/view-tabs.html:88`); every page that drives tabs with Alpine in slot mode drops it. The tab is then only `is-active` — font/weight/border, no accessible selected flag, and `aria-controls` points at a plain `<div>` with no role:

- `pages/articulos/index.html:59-83` (5 buttons, `aria-controls="panel-*"`, no `aria-pressed`)
- `pages/recibos/tablero.html:36-55`
- `pages/inventario/badges.html:14-33` (no `aria-controls` at all)
- `pages/categorias/index.html:55-64`
- `pages/tributacion/consultas.html:54-69`
- `pages/tributacion/dashboard.html:50-89` (six metric-buttons, three of them activate the *same* panel — “resumen” appears 4×, so the mapping is also misleading)
- `pages/settings/index.html:120-129` (wizard steps)

**Why:** VoiceOver/NVDA read “Activos, button” with no indication of which of five views is current — the one piece of state the control exists to convey.
**Fix (page-local, mechanical):** `:aria-pressed="tab === 'activos'"` on each button (or server-rendered `aria-current` where the tab is server-driven), plus `role="region" aria-labelledby="…"` on the panels if you keep `aria-controls`. `_kit/view-tabs.html` should state this in its slot-mode example so the next page copies it.

### P1-6 · A Qute expression is printed literally inside an include parameter
`pages/reportes/ventas-fecha-historica.html:82`
```82:82:app/src/main/resources/templates/pages/reportes/ventas-fecha-historica.html
{#include _kit/surface title="Histórico de ventas para {filtros.dia}/{filtros.mes}"}
```
ui-kit golden rule 13 + §10: a quoted include parameter is literal text; `{…}` inside it is not evaluated. The panel heading therefore renders `Histórico de ventas para {filtros.dia}/{filtros.mes}`. (This is the only occurrence in the tree — verified by scanning every `{#include … ="…{…}…"}`.)
**Fix:** `title=("Histórico de ventas para " + filtros.dia + "/" + filtros.mes)`.

### P1-7 · “Actualizar Dashboard” sits inside the region it replaces
`pages/tributacion/dashboard.html:32-43`: `#tributacion-kpis` wraps the `_kit/page-header`, and the refresh button (`:37-41`) carries `hx-target="#tributacion-kpis" hx-swap="innerHTML"`.
**Why:** after the swap the focused button no longer exists (focus → `body`, no announcement), the whole header — including the page's only `<h1>` — is destroyed and re-inserted, and `x-data="{ tab: 'resumen' }"` at `:32` is re-initialised, silently resetting the operator's selected view.
**Fix:** move the button outside the swap target (a `_kit/action-bar` above it, or target an inner `#tributacion-kpis-datos`), and keep `x-data` outside the swap.

### P1-8 · Group labels are `<label>` elements with no control and no `for`
17 occurrences. A `<label>` that wraps no control and points at no `id` is an accessibility tree no-op (and clicking it does nothing). Radio/checkbox groups need `fieldset`/`legend`; read-only caption labels need `<span class="label">`.

| File:line | What it labels |
|---|---|
| `pages/devoluciones/index.html:52` | “Tipo de Búsqueda” — a radio group (`:54-63`) |
| `pages/correos/form-reporte.html:51,74` | “Frecuencia” (select group), “Reportes” (checkbox group) |
| `pages/usuarios/form.html:58,88` | “Permisos” — checkbox group |
| `pages/clientes/form.html:129` | “Códigos de Actividad Económica (CIIU4)” — multi-input |
| `pages/reportes/ventas-fecha-historica.html:37` | “Elementos (marque los que desea…)” — checkbox group |
| `pages/articulos/form-promocion.html:60`, `articulos/form-revision.html:82,170`, `inventario/form-rapido.html:21,27`, `inventario/form-revision.html:23,29`, `inventario/stock-alert-config.html:115`, `reportes/etiquetas.html:27,31` | read-only captions → `<span class="label">` |

**Fix:** `<fieldset class="field"><legend class="label">Permisos</legend>…</fieldset>` for groups; `<span class="label">` for captions. Two lines each, no visual change.

### P1-9 · Tables inside modal bodies have no scroll frame → clipped at 360
`.table-container` (Bulma `overflow-x:auto`) is missing on the widest tables that live in a `calc(100vw - 1rem)` modal:

- `pages/facturas-recibidas/detalle-drawer.html:77-112` — 7 columns, one of them an `<input style="min-width:9rem">` per row (`:98`); on a 360 px phone the “Total línea” column is unreachable, not scrollable.
- `pages/reportes/estacionalidad.html:71,89,103,(,141)` — five tables, none wrapped; at ≤768 px the `.column.is-half` stacks and each table pushes the page wider than the viewport.
- `pages/loyalty/drawer-historial.html:90`, `pages/inventario/detalles-ajuste.html`, `pages/articulos/detalles.html` (price history) — same, inside a drawer/modal.

**Fix:** wrap each `<table>` in `<div class="table-container">` (the pattern used by `dashboard/index.html:237`, `categorias/index.html:133`, `settings/index.html:614`). One line per table, no CSS.

### P1-11 · `_kit/pagination` declares a parameter it documents as optional
`_kit/pagination.html:35` `{@java.lang.Integer pages}` makes `pages` **required** (Qute fails rendering when a declared param is missing) while `:14-17` and `:57` treat it as optional (`{#if pages??}`). `_kit/data-table.html:123` forwards `pages=pages` from a model that may not carry the key.
**Why:** a caller that legitimately has no page window (`totalPages == 1`) either fails to render or forces every resource to always populate `pages`. It also makes the `{#if pages??}` guard dead code.
**Fix:** delete line 35 (`pages` stays undeclared, like `params` at :37).

### P1-12 · `_kit/data-table` dereferences optional sort params unguarded — needs a render check
`_kit/data-table.html:77,91,93` compare `col.key == sortKey` and `sortKey`/`sortDir` directly. The header at :41-42 documents both as OPTIONAL, and real callers omit them: `tributacion/dashboard.html:126-127,149-150`, `devoluciones/index.html:91-93` (passes page/size but no sort), `tributacion/consultas.html:78,95,112,140` (id + baseUrl + headers only). `_kit/metric.html:16-22` states plainly that in this codebase “a bare `{#if optional}` is a RUNTIME ERROR, not a falsy test”.
**Why it matters:** either these four call sites are already render-erroring in production, or the sort branch silently never activates. Both are bad and the two cannot both be true — this needs one `curl`/test render to settle, which this pass must not run.
**Fix once confirmed:** guard at the top of the header loop — `{#if sortKey??}{#if col.key == sortKey}…{/if}{/if}` — and, since the theme already uses it elsewhere (`compras/ordenes.html:59`), prefer Qute's `?:`/`??` normalisation: `{#let keyOrden = (sortKey ?: '')}` then compare against `keyOrden`.

## 3. P2 — medium / consistency

1. **`.heading` is still the banned uppercase micro-label, 99 times.** `web/mercurius.scss` never remaps `.heading`, so ui-kit §10.1 (“Uppercase tracked micro-labels are gone”) is contradicted by `perfil/index.html:45-57`, `caja/estado-caja.html:45-54`, `settings/index.html:133-202,530-541`. *Shared fix:* `.heading { color: var(--mercurius-text-muted); font-size:.75rem; font-weight:500; letter-spacing:0; text-transform:none; margin-bottom:.25rem; }` — one rule retires 99 instances without touching a template.
2. **`is-striped` on 22 tables** (`tributacion/dashboard.html:96`, `reportes/estacionalidad.html:71,89,103`, `settings/index.html:615`, `facturas-recibidas/detalle-drawer.html:77`, …) contradicts ui-kit §4 (“No zebra striping”). Page-local: delete the class.
3. **`.kit-code` bypassed** by `is-family-monospace` at `tributacion/dashboard.html:131,154` and `tributacion/consultas.html:83,100,117,145`; `articulos/detalles.html:17` and several others still use `style="font-weight:500"` for the identity column (`tabla-articulos.html:82`, `tabla-activos.html:48`, …). ui-kit §10.1: “Monospace is one class”.
4. **Polling helper unused.** `web/index.js:165-234` (`kitPolling`) exists for exactly the two poll sites (`inventario/index.html:46`, `tributacion/consultas.html:43`) and neither carries `data-poll`/`data-poll-age`. Result: both keep polling on a hidden tab, and neither shows freshness. Add `data-poll` (+ `data-poll-age` to a new `<span class="action-count">`).
5. **Duplicate `data-kit-open` bridges — 15 files.** `web/index.js:44-66` installs the delegated handler once, and `fragments/navbar.html:210-230`, `articulos/index.html:229-247`, `cabys/index.html`, `categorias/index.html:175-193`, `clientes/index.html:85-103`, `compras/ordenes.html:98-115`, `correos/reportes.html`, `correos/templates.html`, `facturas/factura-body.html:221-237`, `facturas-recibidas/index.html:74-84`, `inventario/index.html:151-161`, `loyalty/index.html:83-102`, `reportes/clientes.html`, `stockalert-config/index.html`, `usuarios/index.html:84-102` each ship a byte-identical copy. Today they are idempotent; the day one copy learns something (focus return, `aria-expanded`), the other 14 win by listener order. Delete the copies (or narrow them to their page-specific extra, as loyalty correctly does).
6. **`_kit/action-bar` emits `id=""`** when the caller omits `id` (`_kit/action-bar.html:55`, `<div class="action-count" id="{id ? id + '-count' : ''}">`). `pages/loyalty/drawer-historial.html:96` is such a caller. Emit no attribute at all: `{#if id??} id="{id}-count"{/if}`.
7. **`_kit/surface` silently drops `{#actions}` when there is no `title`** (`_kit/surface.html:61-69` renders the header only inside `{#if title??}`). Latent — no caller does it today — but `perfil/index.html:41` is a headerless surface, and the next person to add a control there will lose it with no error. Fix: render `{#insert actions}` in a header whenever `title?? || …` — simplest is to always render `.surface-header` and let CSS collapse it when empty.
8. **`_kit/chart-card` titles are `<p>`, not headings** (`_kit/chart-card.html:63` `<p class="chart-title">`). Every chart sits under an `h2` from `_kit/surface` on report pages, so heading navigation skips the chart entirely; `dashboard/index.html:72-80` has charts with no heading at all. Also `:70` gives the canvas `role="img" aria-label="{title}"`, duplicating the visible `<figcaption>` → double announcement. *Fix:* `<h3 class="chart-title">` + `aria-hidden="true"` on the canvas (the caption labels it).
9. **Loading states that can never end.** `reportes/ventas-fecha-historica.html:93` is a static “Cargando datos…” paragraph; if the page script throws, it stays. `inventario/index.html:68` shows a `0%` progress bar at rest with no `aria-label` (the same component at `facturas-recibidas/index.html:50-51` has one; `recibos/index.html:69` starts `hidden`). Standardise: `hidden` + `aria-label` + `role="progressbar"` semantics inherited from `<progress>`, and a terminal “sin datos” state.
10. **Three copies of the same upload surface.** `inventario/index.html:55-75`, `facturas-recibidas/index.html:37-56`, `recibos/index.html:56-76` are the same filename/label/button/progress block with three different progress behaviours, and none opts into `kitUploadProgress()` (`data-upload-progress`, `web/index.js:86-136`). Consolidate into one include (and decide P2-10's product question below).
11. **`title=` carries meaning that touch/keyboard users cannot get.** `tributacion/consultas.html:124` puts the fiscal justification (“Art. 19 … no se realiza nota de crédito”) only in a `title` on a status chip, and `:127` on the Reemitir button; `consultas.html:45` puts the next send time only in `title`. Tooltips are not focusable. Move the text to a visible `help` line or `aria-describedby`.
12. **`<p class="title">` used as a heading, 50 times.** Worst offenders: `settings/index.html:526` (“Respaldos de Base de Datos”, `title is-4` — louder than the page's `h1`), `:112,546,609`; `tributacion/declaracion.html:59,64,69,73,77` (five `title is-4` figures — these are values, so `title` is the wrong class but not a heading bug); `error/404.html:14` (`title is-1` for “404”). Page-local: `h2` for section titles, `.metric-value`/`.kit-figure` for figures.
